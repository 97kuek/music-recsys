# 研究計画

## 目的・課題

- 音楽推薦システムにLLM・Agentを導入した際の改善と限界を調べる。
- LLMによって推薦精度が必ず改善するという前提は置かない。
- 研究テーマ・仮説は未確定。先行研究と予備実験を通じて絞り込む。

| 対象 | 課題・検証候補 |
| --- | --- |
| 従来型推薦 | コールドスタート、嗜好・文脈の変化、曖昧な要求、多様性・発見性、説明、推薦手法の固定化 |
| LLM | 嗜好理解・条件構造化・説明・再ランキングの効果、ハルシネーション、精度、推論コスト |
| Agent | 動的なツール選択・結果統合・再検索・フィードバックによる調整の追加価値 |

## 比較構成

| 構成 | 候補・役割 |
| --- | --- |
| A：従来型推薦 | Popularity、UserCF、ItemCF、Content-Based、Matrix Factorization、Implicit ALS / BPR、Hybrid |
| B：A + LLM | 嗜好抽出、会話からの条件構造化、検索条件生成、説明、必要に応じた再ランキング。処理順は固定 |
| C：A + LLM + Agent | 要求解釈、推薦・検索ツールの動的選択、CFと内容ベースの使い分け、結果統合、再検索・再ランキング、推薦調整 |

- BとCを区別し、Agentの導入が固定処理より有効かを検証する。
- 共通の構造化嗜好を使うモデル比較と、自然言語理解を含む全体比較を分ける。
- 推薦エンジンをLLM / Agent / UIから独立させる。
- Notebookで検証し、UIは後から作る。

## 進め方

| 段階 | 内容 |
| --- | --- |
| 基盤 | Python環境・文書・共通Runner・Evaluator |
| データ・先行研究 | 利用条件、分割、研究課題・仮説の絞り込み |
| A | Popularityから必要な推薦モデルへ拡張 |
| B | LLMの処理を追加し、Aとの差を評価 |
| C | 動的なツール選択を追加し、Bとの差を評価 |
| 比較・報告 | 定量・定性評価、有効性と限界の整理。満足度・説明の納得感の主観評価も検討 |

- 合成データとMusic4Allの初期検証に、Popularity・Runner・NDCG / Recall・Notebookを使用する。
- Music4Allの100ユーザーでの初期評価条件は決定済み。[データセット方針](dataset-investigation.md)、[評価条件](evaluation-protocol.md#music4allの初回実データ検証)を参照。全量での推薦性能評価は未実施。
- 研究全体の主評価指標・最終評価条件、比較モデル、LLM・Agentの詳細、日程は未確定。
